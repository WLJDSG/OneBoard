# 2026-07-14 开发日志

## 文件暂存类型过滤与截图选区交互升级

### 问题

1. 移动普通应用窗口也可能被识别为文件拖拽并触发暂存区。
2. `.app` 应用包和目录不应作为普通文件进入暂存区。
3. 屏幕顶部框选的截图在进入标注时会出现在屏幕底部，位置呈上下镜像。
4. 鼠标松开后立即裁剪，无法继续移动选区或调整大小。

### 根因

#### 文件暂存

`DragDetector.canConfirmFileDrag` 只检查 drag pasteboard 是否声明 file URL 类型，没有读取真实 URL，也没有判断 URL 对应的是普通文件、目录还是应用包。类型声明可能在窗口拖动期间残留或复用，导致误触发；确认成功后又会在整轮拖拽中缓存错误状态。

#### 截图位置

CGImage 使用左上原点，AppKit 屏幕和窗口使用左下原点。旧实现让裁剪坐标和窗口定位共用 Y 轴翻转，导致选区已经是 AppKit 坐标时又被翻转一次，顶部选区因此出现在底部。

#### 截图调整

旧遮罩在 `mouseUp` 中直接调用裁剪确认，选区没有独立的 adjusting 阶段，也没有可测试的移动、缩放和锁定状态。

### 修复内容

#### 文件暂存

- 从 drag pasteboard 读取真实 file URL 后再确认拖拽。
- 使用文件系统 `isRegularFile` 判断普通文件，不维护扩展名白名单。
- 显式拒绝 `.app`、目录、无效 URL 和不可读取路径。
- `FileStagingViewModel.addFile` 使用相同规则做入口防御，避免直接拖入暂存窗口绕过检测。

#### 截图坐标

- `cropRect` 保留 Y 轴翻转，只负责从 Overlay 逻辑点转换为 CGImage 像素。
- `screenRect` 只叠加当前屏幕原点，不再翻转 Y。
- Retina 图像继续保留原始像素，标注窗口使用框选逻辑点尺寸和原始屏幕位置。

#### 截图选区

- 新增 selecting、adjusting、locked 三阶段选区模型。
- 鼠标松开后保留选区；拖动内部可移动，四边和四角共八个控制点可缩放。
- 在选区外重新拖动可以重新框选，所有几何操作受当前屏幕边界和最小尺寸约束。
- 调整阶段显示截图工具栏，并根据屏幕空间自动放到选区上方或下方。
- 点击矩形、圆形、箭头、直线、文字、编号或马赛克后直接锁定选区，并以对应工具进入标注。
- 复制、保存、贴图、OCR 和翻译同样先锁定当前区域再执行。
- 锁定只允许成功一次；进入标注后不再响应选区移动或缩放。

### 回归测试

新增或扩展：

- `DragDetectorTests`：真实普通文件通过；目录、`.app` 和只有类型没有 URL 的拖拽被拒绝。
- `ScreenshotOverlayCropTests`：顶部选区保持顶部，同时 CGImage 裁剪继续正确翻转 Y。
- `ScreenshotSelectionTests`：移动边界、八方向缩放、最小尺寸、重新框选、工具栏定位和一次性锁定。
- `ScreenshotSessionLifecycleTests`：标注工具和输出动作路由。

### 人工验收边界

当前自动化测试覆盖坐标与状态机，但真实 macOS 全局鼠标手势仍需在安装包中肉眼确认：

1. 分别在屏幕顶部、中央和底部框选，松开后选区位置不变。
2. 移动选区并拖动八个控制点，确认不越过屏幕边界。
3. 点击标注工具后确认立即锁定，进入标注后无法继续改变截图范围。
4. 拖动 txt、表格、图片和压缩包可触发暂存；移动应用窗口、拖动目录或 `.app` 不触发。

## 权限重启、内嵌截图标注与面板一致性修复

### 用户反馈

1. 录屏授权后的“退出并重新打开”只退出，没有再次启动 OneBoard。
2. 截图框选后同时保留选区并新增图片窗口，完整工具栏还可能被遮罩覆盖。
3. 内嵌标注后，鼠标移动方向与标注绘制方向相反。
4. 彻底卸载没有可靠清除辅助功能授权记录。
5. 暂存架有文件后整体样式变化；翻译标题栏控件重叠；网关切换面板层级不清晰。

### 根因

- `applicationShouldTerminate` 只允许系统结束进程，但菜单栏应用在系统权限流程中不会稳定地被系统再次拉起。
- 截图流程保留了全屏遮罩，同时仍通过 `showAnnotationWindow` 创建独立图片窗口；调整窗口 level 无法解决重复窗口的架构问题。
- 内嵌画布使用的 `NSHostingView` 已经是 flipped 坐标系，鼠标事件转换又执行一次 `height - y`，导致 Y 轴二次翻转。
- 命令行卸载脚本先删除 App，再静默执行 `tccutil reset`；删除后系统可能无法再根据 Bundle ID/代码签名识别客户端，失败也不会反馈。
- 暂存文件增删会替换整个 `NSHostingView`；翻译服务 Picker 的 `fixedSize` 会突破标题栏约束。

### 最终实现

- 录屏和输入监控授权流程活跃时收到系统终止请求，启动独立 shell 进程，延迟 1 秒执行 `open -n` 重新打开当前 App。
- 框选完成后直接在同一个遮罩窗口内创建 `AnnotationCanvasView` 和完整 `AnnotationToolbarView`，不再显示精简工具栏，也不再创建第二张图片窗口。
- `AnnotationViewModel` 根据目标 `NSView.isFlipped` 决定是否转换 Y 轴；嵌入画布禁止通过 cursor 工具拖动整个全屏窗口。
- 卸载流程先清理所有 TCC 服务，再删除 App；Accessibility 对主 Bundle ID 单独重试，并保留失败日志/提示。
- 暂存架复用同一个 HostingView，由 `@ObservedObject` 更新内容；空态和文件态共享固定内容骨架。
- 翻译服务分段选择器使用受控宽度；网关面板改为带当前状态、切换反馈和 DNS 信息的卡片布局。

### 验证

定向测试覆盖：

- `NSHostingView.isFlipped == true` 的真实运行时属性。
- flipped 画布中鼠标向右、向下移动时，标注坐标保持同方向。
- 非 flipped AppKit 视图只执行一次 Y 轴转换。
- 截图选区几何、截图会话关闭、权限状态切换与卸载脚本语法。
