# 2026-07-17 开发日志

## 多显示器截图、统一工具栏、Finder 桌面与网关安全边界修复

### 问题范围

1. 截图只创建一个主屏遮罩，并把整张截图按主屏逻辑尺寸裁剪；混合 Retina/非 Retina 或在外接屏框选时可能出现比例和位置错误。
2. 选区调整阶段与标注阶段维护两套工具栏，工具选择只更新局部状态时可能没有锁定选区或安装标注画布；画布切换还可能吞掉第一次鼠标按下。
3. OCR 按钮曾绕过截图会话完成路径直接显示结果气泡，导致全屏遮罩仍在并覆盖结果窗口。
4. Finder 桌面监听只依赖固定路径，未完整覆盖系统解析桌面、iCloud Desktop 和符号链接目标；Extension entitlement 也需要与目录范围保持一致。
5. 网关 Helper 安装后再同步白名单会触发两段授权流程；Helper 返回地址不在白名单时，旧回退判断还可能把业务拒绝误判为 Helper 不可用并尝试管理员命令。

### 根因

#### 多显示器截图

原实现使用一次无显示器编号的 `screencapture` 和一个主屏 `NSWindow`。不同显示器的 frame、scale factor 和图像像素尺寸没有一一对应，裁剪只能隐含假设主屏比例。

#### 工具栏与截图会话

`ScreenshotSelectionToolbarView` 和 `AnnotationToolbarView` 分别处理调整与标注动作，能力与生命周期容易漂移。标注工具选择需要由 Overlay 层推进 `adjusting → locked` 并创建画布；OCR 等输出也需要由会话层统一关闭遮罩，不能在工具栏内部直接弹窗。

#### Finder 桌面

桌面可能位于传统 `~/Desktop`、iCloud Desktop，也可能通过系统 API 或符号链接解析到其他实际路径。只注册字符串路径会漏掉 Finder 当前使用的目录；沙盒 entitlement 如果不同步，也会造成菜单或目录访问不一致。

#### 网关 Helper

安装脚本只创建空白白名单，随后再执行一次 `sudo -n` 同步，形成额外授权窗口。`GatewaySwitcher` 又把所有包含 `not allowed` 的错误当成执行能力失败，没有区分“无法执行 Helper”和“Helper 按白名单主动拒绝”。

### 修复内容

#### 多显示器独立捕获

- 按 `NSScreen.screens` 为每块显示器生成 `ScreenshotDisplayCapturePlan`，使用 `screencapture -D <displayNumber>` 分别捕获。
- 每块显示器创建一个与 `screen.frame` 对齐、可成为 key window 的独立遮罩；优先激活鼠标所在屏幕。
- 每个 Overlay 只用自己的局部 `bounds` 与对应图像做裁剪，不再用主屏 frame 解释外接屏像素。
- 任意屏幕确认或取消后统一清理全部事件监听和遮罩窗口，continuation 只恢复一次。

#### 统一工具栏与输出生命周期

- 调整与标注阶段统一复用完整 `AnnotationToolbarView`，删除 `ScreenshotSelectionToolbarView`。
- 标注工具点击回调交给 `ScreenshotOverlayContentView`，立即锁定选区、裁剪当前图像并安装 `AnnotationCanvasView`。
- 画布在第一次鼠标按下期间安装时，将该事件和坐标显式转交 `AnnotationViewModel.beginInteraction`，保证首笔不丢失。
- OCR、翻译、复制、保存和贴图全部返回截图会话完成路径；先关闭所有遮罩，再执行对应输出或显示结果窗口。

#### Finder Desktop 兼容

- 监听集合同时纳入 `/`、用户目录、传统 Desktop、iCloud Desktop 和 `FileManager` 解析出的桌面目录。
- 每个候选目录同时保留标准化路径和符号链接解析路径。
- Finder Sync entitlement 增加 `/Desktop/` 与 `/Library/Mobile Documents/com~apple~CloudDocs/Desktop/` 两个 home-relative 读写例外；扩展仍只传递 URL 请求，实际写入继续由主应用完成。

#### 网关 Helper v3

- Helper 版本升级为 `ONEBOARD_GATEWAY_HELPER_VERSION=3`。
- 安装时过滤合法 IPv4、去重并排序，在同一次管理员授权中写入 Helper、sudoers 和初始白名单。
- Helper 的 `Router/DNS is not allowed` 作为最终业务错误直接返回，不再进入 AppleScript 管理员命令回退。
- 保留 Profile 变化后的受限白名单同步，sudoers 仍只允许 OneBoard 专属 Helper 路径。

### 打包与最终产物验收

标准打包命令：

```text
ONEBOARD_CODESIGN_IDENTITY=- script/package_app.sh
```

沙盒内首次执行在 `hdiutil create` 阶段报“设备未配置”；在沙盒外使用同一脚本重新执行后成功生成 DMG。最终验证结果：

```text
hdiutil verify build/OneBoard.dmg
checksum of "build/OneBoard.dmg" is VALID

codesign --verify --deep --strict /Volumes/OneBoard/OneBoard.app
valid on disk
satisfies its Designated Requirement
```

挂载最终 DMG 后已确认：

- `OneBoard.app`、Finder Sync Extension 和 LaunchAtLogin Helper 均通过签名校验。
- Finder Sync Extension 的最终签名 entitlement 包含 App Sandbox、App Group、本地 Desktop 和 iCloud Desktop 例外。
- 镜像包含 `Applications` 软链接、隐藏统一卸载脚本和 `卸载残留.command`。

### 人工验收边界

自动化测试、Release 构建、签名和 DMG 校验已完成；以下真实 macOS 交互仍需在目标机器上人工确认：

1. 主屏和外接屏分别框选，特别是混合 Retina/非 Retina、左右或上下排列时，遮罩、裁剪和工具栏均在对应屏幕原位显示。
2. 每类标注工具点击后立即锁定，第一次按下即可产生标注；进入画布后选区不能继续移动或缩放。
3. 点击 OCR/翻译后所有屏幕遮罩先关闭，结果窗口不被覆盖。
4. Finder 在本地 Desktop、iCloud Desktop 和符号链接桌面的空白处均显示新建菜单，并由主应用成功创建文件。
5. 网关 Helper 首次安装只弹出一次管理员授权；尝试未进白名单的 Router/DNS 时直接失败且不弹出绕过授权。
