# 2026-09-04 Touch ID 敏感操作授权

## 目标

- 网关切换不再弹 AppleScript 管理员密码框，改为系统 Touch ID 确认；没有可用指纹时使用 Mac 登录密码。
- 同步覆盖 Helper 卸载和 App 内彻底卸载，同时保持最小权限与白名单边界。

## 实现

- 新增 `SensitiveOperationAuthorizer`，统一使用 `LAContext.evaluatePolicy(.deviceOwnerAuthentication)`。
- 网关切换在执行 Helper 前完成设备所有者验证；Helper 不可用时直接提示安装或升级，不再回退到管理员 shell。
- Gateway Helper 升级为 v4，增加 `--uninstall` 受限自卸载命令；Helper 卸载与彻底卸载不再启动 AppleScript 管理员授权。
- DMG/命令行卸载脚本优先调用 Helper v4 自卸载；只有旧版或损坏的特权残留才回退到一次终端管理员授权。
- 首次安装或升级 Helper 仍由 macOS 完成一次系统管理员授权，因为 Touch ID 用户确认本身不授予 root 权限。

## 安全边界

- Helper 仍只接受配置档白名单中的合法 IPv4，业务拒绝不得降级执行。
- sudoers 仍只放行 `/usr/local/bin/oneboard-gateway-helper`，未增加任意 shell 或系统命令权限。
- 用户取消 Touch ID/登录密码验证后，不执行网关切换、Helper 卸载或彻底卸载。

- sidecar 使用 `Database::memory()`；OneBoard 从 `oneboard.sqlite` 读取供应商和 Key，经 stdin 注入一次性运行快照，不创建自己的持久化数据库。

## 内置代理 HTTPS 连接重置修复

- 真实 Claude Code 请求到达本地代理后返回空响应，客户端持续提示 `ECONNRESET`；同时 `/health` 仍为 200。
- 通过带 stderr 的独立 sidecar 重放确认：CC Switch 依赖图同时启用了 Rustls 的多个加密后端，首次 HTTPS 转发时因未安装进程级 `CryptoProvider` 而在 worker 线程 panic。
- sidecar 启动最初显式安装 Rustls ring provider，并增加回归测试保证 HTTPS 转发前 provider 已就绪。
- 同一条最小请求在修复前稳定得到 `curl: (52) Empty reply from server`，修复后真实 HTTPS 上游返回 HTTP 200；SSE 返回 `message_start`、`message_delta`、`message_stop`。
- 安装修复版后，真实 `claude -p --model 'deepseek-v4-flash[1M]' '只回复你好'` 在 4.85 秒内成功返回“你好”，`stop_reason=end_turn`，无重试或连接重置。
- 修复版重新通过 2 项 Rust 测试、142 项 Swift 测试、Release 打包和 `hdiutil verify`；最终 DMG SHA-256 为 `405a45c91eddc8acc4796818b7092631298c209162d3fc79a29d8975a06fd8a8`。
