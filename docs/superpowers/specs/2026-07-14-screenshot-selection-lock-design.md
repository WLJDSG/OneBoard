# 截图选区原位调整与标注锁定设计

> 实现演进说明（2026-07-17）：当前版本已在此三阶段模型上改为“每块显示器独立捕获与遮罩”，并在 adjusting/annotating 阶段复用完整 `AnnotationToolbarView`。本文保留 2026-07-14 的设计决策背景，当前规则以 `docs/技术规范/README.md` 和 `开发日志/2026-07/2026-07-17.md` 为准。

## 背景

当前截图流程在鼠标松开时立即裁剪，并将裁剪结果放入独立标注窗口。该流程存在两个问题：

1. 选区位于屏幕顶部时，标注窗口可能出现在屏幕底部。原因是裁剪坐标与屏幕窗口坐标共用了 Y 轴翻转逻辑；CGImage 裁剪需要从 AppKit 左下原点转换到图像左上原点，而 AppKit 窗口定位不需要再次翻转。
2. 鼠标松开后立即结束选区阶段，用户无法继续移动选区或调整大小。

## 目标

- 选区在屏幕上的位置保持不变，不发生上下镜像或跳动。
- 鼠标松开后保留选区，允许移动和八方向缩放。
- 截图工具栏显示在选区附近。
- 点击任意标注工具时直接锁定当前选区，并进入标注阶段。
- 进入标注阶段后不再允许调整选区。
- 复制、保存、钉住、OCR 和翻译统一使用锁定后的截图内容。

## 非目标

- 不支持标注开始后重新调整截图范围。
- 不在调整选区时实时迁移已有标注。
- 不增加跨屏幕拖动选区的能力；选区限制在开始截图时对应的屏幕内。
- 不重构与本次交互无关的标注工具或截图存储逻辑。

## 交互状态

截图会话分为三个明确状态：

### 1. selecting

- 鼠标按下并拖动以创建选区。
- 鼠标松开后进入 `adjusting`，不裁剪、不关闭遮罩。
- 按 Esc 取消整个截图会话。

### 2. adjusting

- 保留选区边框和八个缩放控制点。
- 拖动选区内部移动选区。
- 拖动四角或四边控制点调整选区大小。
- 在选区外按下并拖动时，清除旧选区并开始新的框选。
- 选区始终限制在当前屏幕边界内，并保持最小可用尺寸。
- 工具栏跟随选区定位；优先位于选区下方，空间不足时放到上方，并限制在当前屏幕可见区域内。
- 点击不产生标注的操作（复制、保存、钉住、OCR、翻译）时，先锁定选区，再执行对应操作。
- 点击矩形、箭头、文字、编号、马赛克等任意标注工具时，直接锁定选区并进入 `annotating`。
- 按 Enter 或双击选区也可锁定并进入默认标注状态，但不作为主要操作路径。
- 按 Esc 取消整个截图会话。

### 3. annotating

- 按锁定瞬间的选区裁剪原始屏幕图像。
- 标注画布窗口使用锁定选区的 AppKit 屏幕坐标原位显示。
- 关闭遮罩和选区控制点，禁止继续移动或缩放截图范围。
- 保留现有标注、撤销/重做、复制、保存、钉住、OCR、翻译及关闭能力。

## 坐标模型

坐标转换拆成两个职责明确的函数：

1. `cropRect`：把 Overlay/AppKit 左下原点坐标转换为 CGImage 左上原点像素坐标。该转换保留 Y 轴翻转。
2. `screenRect`：把 Overlay 局部坐标转换为 AppKit 全局屏幕坐标。该转换只叠加 `screenFrame.minX/minY`，不翻转 Y。

因此，对于屏幕顶部的选区，裁剪仍取得正确像素，同时标注窗口复用原始屏幕位置，不再出现在底部。

## 组件调整

### ScreenshotOverlayContentView

- 用显式状态代替当前“鼠标松开立即完成”的布尔流程。
- 负责创建、移动、缩放和重建选区。
- 绘制选区边框、八个控制点与尺寸提示。
- 负责命中测试和屏幕边界约束。
- 在锁定前持有完整屏幕截图，不提前生成裁剪图片。

### 选区几何辅助类型

- 抽离纯几何计算，描述移动、八方向缩放、最小尺寸及边界裁剪。
- 不依赖窗口或鼠标全局状态，便于通过单元测试验证。

### 截图工具栏

- 调整阶段显示在选区附近。
- 工具按钮触发统一的 `lockSelection` 入口。
- 标注工具在锁定完成后继续执行其原有选中动作。
- 非标注操作在锁定完成后执行复制、保存、钉住、OCR 或翻译。

### ScreenshotViewModel

- 接收锁定后的 `ScreenshotResult`。
- 继续负责创建标注画布和工具栏、执行输出操作及关闭截图会话。
- 标注窗口原点直接使用修正后的 AppKit `selectionRect.origin`。

## 数据流

1. 启动截图并缓存当前屏幕的原始 CGImage。
2. 用户拖动产生 Overlay 局部选区。
3. 鼠标松开后进入调整状态，显示控制点与工具栏。
4. 用户移动或缩放选区，纯几何逻辑持续约束选区。
5. 用户点击工具按钮。
6. `lockSelection` 固化当前选区，只执行一次裁剪，并生成 `ScreenshotResult`。
7. 关闭截图遮罩，在相同屏幕位置显示标注画布。
8. 若触发源是标注工具，则进入对应工具；若是输出操作，则执行操作后按现有规则继续或关闭会话。

## 边界与错误处理

- 小于最小尺寸的选区不能锁定，并继续停留在调整状态。
- 裁剪结果为空或越界时不关闭遮罩，允许用户重新调整。
- 多次快速点击工具只允许第一次锁定生效。
- 工具栏定位使用当前选区所在屏幕，不使用固定的主屏幕坐标。
- Retina 屏幕只在裁剪阶段换算像素比例；窗口布局始终使用逻辑点。
- 多显示器负坐标通过叠加对应 `screenFrame.origin` 处理，不假设主屏幕原点为零。

## 测试与验收

### 单元测试

- 屏幕顶部选区转换为全局屏幕坐标后仍位于顶部。
- 裁剪坐标继续正确执行 Y 轴翻转。
- Retina 像素比例下裁剪范围正确。
- 选区移动受四个屏幕边界约束。
- 八个控制点分别产生正确的缩放结果。
- 缩放不会小于最小尺寸。
- 在选区外重新拖动会进入新的选择状态。
- 首次标注工具操作锁定选区，锁定后调整事件不再改变选区。
- 工具栏在选区下方空间不足时切换到上方，并保持在可见区域内。

### 构建与打包验收

- 运行截图相关测试与完整 `swift test --disable-sandbox`。
- 运行 Release 构建。
- 使用 `ONEBOARD_CODESIGN_IDENTITY=- script/package_app.sh` 重新打包。
- 使用 `hdiutil verify build/OneBoard.dmg` 校验镜像。

### 人工交互验收

- 分别在屏幕顶部、中央、底部框选，松开后选区位置不变。
- 移动选区并测试八个方向的缩放。
- 点击任意标注工具后选区立即锁定，不能再调整。
- 标注内容、复制或保存结果与锁定区域一致。
- 在 Retina 与多显示器环境确认无上下镜像和跨屏跳动。
