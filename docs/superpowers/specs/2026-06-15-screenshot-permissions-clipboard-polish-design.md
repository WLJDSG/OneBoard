# OneBoard 截图、权限、剪贴板体验修整设计

日期：2026-06-15

## 背景

本次修整覆盖 7 个用户反馈点：

1. DMG 安装到 `/Applications` 后，开机自启开关仍会立即弹回关闭，并提示无法启用。
2. 截图标注工具栏不够美观；去掉复制按钮，新增对钩按钮，点击后复制当前截图并关闭。
3. 一张截图停留在标注工具栏状态时，再截一张图，会导致上一张截图无法关闭。
4. 翻译工作台头部留白过多，整体布局需要优化，并保证界面完整。
5. OCR 识别文字结果要改成贴近截图内容的气泡弹窗，点击外部空白处可立即关闭。
6. 点击剪贴板历史条目进行粘贴时，会被监控服务当作新的复制行为并生成重复记录。
7. 权限页关闭屏幕录制或清除权限后，开关状态和文案没有正确变化；关闭一个权限时另一个权限也出现视觉变化。

## 已确认决策

- 截图工具栏采用 `B + C 混合`：紧凑、高频操作直接可见，同时按工具、颜色、动作分组。
- 工具栏移除独立复制按钮；新增绿色对钩按钮。
- 对钩按钮行为：渲染当前截图和标注，复制到剪贴板，关闭截图编辑窗口和工具栏。
- 翻译工作台采用 `B 上下阅读流`，关闭按钮更靠右上角。
- 第 4 点只调整翻译工作台，不把 OCR 或截图标注窗口纳入“工作台”概念。
- OCR 结果使用气泡弹窗，位置贴近截图文字/截图内容区域，点击外部空白处关闭。
- 用户通过 DMG 安装到 `/Applications/OneBoard.app` 后启动，开机自启开关仍立即失败。

## 设计方案

### 1. 开机自启

保留现有 `LaunchAtLogin` 依赖，优先修复打包链路，而不是重写一套自启实现。

当前打包脚本已经把 `LaunchAtLoginHelper.app` 解压到 `Contents/Library/LoginItems`，但还缺少稳定注册所需的完整验证链路。实现时需要：

- 在 `script/build_app_bundle.sh` 中检查 helper 是否存在、bundle id 是否与主 app 匹配。
- 对 helper 和主 app 执行 ad-hoc 签名，确保 Launch Services 能识别嵌套登录项；正式证书签名和 notarization 不纳入本次范围。
- 打包完成后可加入轻量验证输出，例如打印主 app bundle id、helper bundle id、签名状态。
- 设置页失败文案改得更具体，避免只提示“完整 .app 启动”。

验收：

- 从 DMG 拖到 `/Applications` 后启动。
- 打开“开机自启”开关后，开关保持打开。
- 关闭后开关保持关闭。

### 2. 截图工具栏

工具栏继续作为独立悬浮面板跟随截图窗口，但视觉和信息架构调整为：

- 左侧：标注工具组，保持光标、矩形、圆形、箭头、直线、文字、打码。
- 中间：颜色组，直接展示更多预设色，包含红、橙、黄、绿、青、蓝、紫、粉、黑、白，并保留系统颜色面板入口。
- 右侧：动作组，保留保存、贴图、OCR、翻译、撤销、关闭或完成。
- 移除“复制”按钮。
- 新增绿色对钩“完成”按钮，语义是复制并关闭。

对钩实现：

1. 调用 `AnnotationService.renderToImage(baseImage:displaySize:)` 生成最终图片。
2. 调用 `ScreenshotViewModel.copyToClipboard(_:)` 写入剪贴板。
3. 关闭截图编辑窗口、工具栏、关联 OCR 气泡。

验收：

- 点击对钩后剪贴板中是标注后的最终截图。
- 截图编辑窗口和工具栏都关闭。
- 工具栏按钮不挤压、不裁切，颜色入口可用。

### 3. 截图窗口生命周期

`ScreenshotViewModel.startCapture()` 开始新截图前先清理当前编辑态窗口：

- 关闭 `annotationWindow`。
- 关闭 `toolbarPanel`。
- 关闭 OCR 结果气泡。
- 关闭翻译工作台。
- 失效 frame observer。

同时，窗口关闭逻辑要做到幂等：重复调用不会崩溃，也不会留下孤儿面板。

验收：

- 第一张截图停留在工具栏状态时，再触发截图。
- 第二张截图完成后，第一张不会残留无法关闭的窗口。
- Esc、关闭按钮、完成按钮都能稳定清理当前窗口。

### 4. 翻译工作台

采用 mockup B：上下阅读流。

布局调整：

- 标题栏高度压到约 44pt。
- 标题左侧显示“翻译工作台 · 当前服务”。
- 关闭按钮贴近右上角，保留足够点击区域。
- 服务切换使用紧凑 segmented control。
- 语言选择区横向排列：源语言、交换按钮、目标语言。
- 原文和译文保持上下结构，区域高度重新分配。
- 状态文案和底部按钮保持完整可见。

窗口完整性：

- 保持固定宽高，并在面板层设置相同的最小宽高，避免内容被系统压缩。
- 控件之间使用稳定 spacing 和 frame，避免系统字体或语言文案变化造成裁切。
- 底部按钮区域不被内容区挤出。

验收：

- 图 3 中的顶部留白消失。
- 关闭按钮更靠右上。
- Apple、Google、DeepSeek、语言、原文、译文、状态、按钮都完整显示。

### 5. OCR 气泡弹窗

新增专门的 `OCRBubbleWindowManager`，避免把翻译/通用结果浮窗和 OCR 气泡行为混在一起。

行为：

- OCR 完成后，在截图窗口附近显示白色气泡。
- 气泡包含标题“提取文字”、识别结果、关闭按钮、编辑按钮、复制按钮。
- 点击气泡外部空白处立即关闭。
- 气泡应有小尖角指向截图内容区域。

位置：

- 优先靠近当前截图窗口或识别内容区域。
- 若超出屏幕，自动改到可见范围内。

验收：

- 点击 OCR 后显示气泡弹窗，而不是普通矩形结果窗。
- 点击外部空白处立刻关闭。
- 复制按钮可复制识别结果。
- 编辑按钮允许用户修改识别文本后再复制。

### 6. 剪贴板重复记录

当前 `PasteboardMonitor` 已有 `performIgnoringChanges` 和 `isPasting` 机制，但 `ClipboardListViewModel.selectAndPaste(_:)` 主要靠手动设置 `isPasting`，异步链路结束和 changeCount 同步不够稳。

调整为：

- 点击历史条目后，把“写入剪贴板、关闭面板、激活目标 app、模拟 Cmd+V”的完整流程包进忽略监控区。
- 结束时同步 `lastChangeCount` 到当前 `NSPasteboard.general.changeCount`。
- 即使目标 app 不存在、缺少辅助功能权限或粘贴失败，也要恢复监控状态。

验收：

- 点击某条剪贴板历史记录粘贴，不会新增一条相同记录。
- 普通外部复制仍能正常记录。
- 缺少辅助功能权限时，不会永久暂停剪贴板监听。

### 7. 权限状态刷新

权限页需要让“操作中的意图”和“系统真实状态”分离，避免一个开关操作让另一个开关跟着跳。

调整方向：

- 单独关闭屏幕录制时，只执行屏幕录制 reset，并只设置屏幕录制相关状态消息。
- 单独关闭辅助功能时，只执行辅助功能 reset，并只设置辅助功能相关状态消息。
- `refresh()` 仍读取两个真实权限，但在 reset 后增加延迟二次刷新，缓解 TCC 状态缓存。
- `清除全部授权` 后同时刷新权限、helper、自启，并更新统一文案。
- 设置页开关可在操作过程中短暂禁用，避免用户连续点击造成状态交错。

验收：

- 关闭屏幕录制时，辅助功能开关不会无故视觉跳变。
- 清除全部权限后，文案和开关状态能跟随变化。
- 状态刷新不会长期停留在旧文案。

## 测试计划

- 运行 `swift build` 验证编译。
- 运行现有测试，重点关注：
  - `SystemCapabilityViewModelTests`
  - `TranslationPanelViewModelTests`
  - `AnnotationServiceTests`
- 手动测试：
  - DMG 安装到 `/Applications` 后验证开机自启开关。
  - 截图、标注、点击对钩，确认剪贴板内容和窗口关闭。
  - 连续截图，确认旧窗口不会残留。
  - OCR 气泡显示、编辑、复制、外部点击关闭。
  - 翻译工作台完整显示。
  - 点击剪贴板历史粘贴不产生重复记录。
  - 权限页单独关闭屏幕录制、单独关闭辅助功能、清除全部授权。

## 非目标

- 不新增截图工具类型。
- 不改变翻译服务能力本身。
- 不重写数据库或剪贴板存储模型。
- 不处理 notarization 或正式 Developer ID 分发；本次只保证本地 DMG 安装包的自启功能可用。
