## 二、翻译功能修复

### 2.1 问题描述

**现象**：在任何应用中选中文字后，按下 `Option+Shift+A` 快捷键，弹出提示"没有检测到选中的文字"，但实际文字已被选中。

**影响范围**：
- `ScreenshotViewModel.translateSelectedText()`（翻译选中文字快捷键）
- `TodoListViewModel.addSelectedTextFromFrontmostApp()`（添加选中文字到待办快捷键，使用相同机制）

### 2.2 根因分析

`SelectedTextReader` 使用 `CGEvent.post(tap: .cghidEventTap)` 模拟 Cmd+C 来获取选中文字。该机制需要以下系统权限：

| 权限 | 用途 | 缺失后果 |
|------|------|---------|
| **辅助功能（Accessibility）** | CGEvent 通过 HID 层发送到前台应用 | 事件被系统静默丢弃，Cmd+C 无效 |
| **输入监控（Input Monitoring）** | 部分 macOS 版本也要求此权限 | Cmd+C 可能不生效 |

当前代码在 `translateSelectedText()` 中**没有检查权限状态**，当权限缺失时：
- `sendCopyShortcut()` 发送 Cmd+C → 系统静默丢弃
- 180ms 后剪贴板 changeCount 未变化 → `copiedText = ""`
- 显示"没有检测到选中的文字"

### 2.3 功能需求

| # | 需求 | 优先级 |
|---|------|--------|
| FR-1 | 调用翻译前检查辅助功能权限是否已授予 | P0 |
| FR-2 | 权限缺失时弹出明确提示，告知用户需要开启的权限及操作步骤 | P0 |
| FR-3 | 增加剪贴板变更的轮询等待（当前仅等待 180ms 一次），提高慢速应用的兼容性 | P1 |
| FR-4 | 同样修复"添加选中文字到待办"功能的权限检查 | P1 |
| FR-5 | 提供降级方案：若 CGEvent 方式失败，尝试使用 Accessibility API（AXUIElement）直接读取选中文本 | P2 |

### 2.4 验收标准

- [ ] 权限已授予时，翻译快捷键正常工作
- [ ] 权限未授予时，弹出明确提示（而非"没有检测到选中的文字"）
- [ ] 提示信息包含具体的权限名称和开启路径（系统设置 → 隐私与安全性 → 辅助功能）
- [ ] 权限已授予但仍失败时（如无选中文字），给出准确提示

## 三、全界面 UI 重构

### 3.1 当前问题总结

经过全量 UI 审计（共 17 个窗口/页面），发现以下系统性问题：

| 问题类别 | 具体问题 | 影响范围 |
|---------|---------|---------|
| **设计令牌未统一** | `OneBoardColors` 仅被 3/6 模块使用，其余使用原始系统色 | 全局 |
| **材料风格不一致** | `.ultraThinMaterial` 和 `.regularMaterial` 混用且无规则 | 5个浮动窗口 |
| **圆角无体系** | 11 种不同圆角值（2/4/5/6/7/8/9/10/12/14/18/24） | 全局 |
| **阴影无体系** | 5 种不同阴影参数 | 全局 |
| **无字体系统** | 字体大小分布在 7-48pt，无 TextStyle 定义 | 全局 |
| **硬编码颜色** | FileStaging 使用 `Color.black/white.opacity()` 不支持深色模式 | FileStaging 模块 |
| **AccentColor 混乱** | 部分组件使用 `.accentColor`（系统蓝），部分使用 `OneBoardColors.primary`（自定义淡蓝） | Gateway/Translation/Todo |
| **死代码** | `nsPrimary/nsPrimaryLight/nsPrimaryDark` 声明但从未使用 | OneBoardColors |
| **双层样式定义** | FileStaging 同时在 AppKit 层和 SwiftUI 层设置圆角和背景 | FileStaging |

### 3.2 设计目标

1. **统一**：一个设计系统覆盖所有 UI 页面
2. **原生感**：遵循 Apple Human Interface Guidelines for macOS
3. **和谐**：色彩、间距、圆角、阴影、字体形成完整体系
4. **可为**：不引入新依赖，使用现有 SwiftUI + AppKit 技术栈
5. **不破坏功能**：重构过程中保持所有功能正常

### 3.4 设计原则

1. **少即多**：减少视觉噪音，强调内容层级
2. **系统优先**：优先使用系统颜色和材料，品牌色仅用于强调
3. **一致性**：相同元素在所有页面中外观一致
4. **可访问性**：确保足够的对比度和可读性
5. **深色模式原生支持**：不依赖硬编码颜色值

### 3.5 验收标准

- [ ] 所有页面使用统一的设计令牌
- [ ] 深色/浅色模式切换后所有 UI 可读
- [ ] 无硬编码颜色值（除设计令牌定义外）
- [ ] 无死代码
- [ ] 所有现有功能正常工作
- [ ] swift build 编译通过
